# 30. 운전 상태별 모델 채택 여부 / 오류분석 타당성 재검토 / 필수 시각화

작성 2026-10-06 / 실행 `state_model_test.py`(185초) · `missed_event_taxonomy.py`(3초) · `state_visuals.py`(25초)
표기: **[사실]** 생성 표 수치 · **[해석]** 설명 · **[가설]** 미검증

> **결론 먼저**
> 1. **상태별 개별 예측모델은 채택하지 않는다.** 4개 horizon 전부에서 전체 모델보다 나쁘고(h60 +0.756 kw),
>    일 블록 bootstrap 95% CI 가 0을 넘지 않는다. 사전 선언한 채택 조건 4개 중 **0개** 충족.
> 2. **"데이터에 자연적 군집이 3개 있다" 는 주장은 성립하지 않는다.** silhouette 최적은 **k=4**,
>    규칙 라벨과 KMeans3 의 ARI 는 0.21. `3` 은 **설계상 정한 개수**다.
> 3. 미탐 사건은 **전부 임계를 0.50 분위로 낮추면 포착**된다 → "본질적 예측 불가"·"센서 부족" 으로
>    부를 수 없다. 오류분석은 **원인 설명이 아니라 실패 위치 탐색 결과**로 격하한다.

## 1. 현재 상태 정의와 사용 범위 — 코드 추적 결과 **[사실]**

| 결정시점 정보만? | **예.** `is_operating`·`is_operating_lag4`·`kw_ramp4` 모두 t 시점 값. ramp 컷은 폴드 TRAIN p90 (`pipeline.py:41`) |

**[해석]** 따라서 "3상태로 예측모델을 나눈다" 는 것은 현재 구현에 **없는 설계**이며, 이번 실험은
그 도입 여부를 처음 직접 검증한 것이다.

### 1.1 "상태 3개" 와 "군집 3개" 는 다르다 **[사실]** `30_cluster_count_check.csv`

첫 폴드 학습구간, 표준화 `[kw, kw_ramp4, kw_std4, kw_roll4]` 에서 KMeans k=2~6:

| k | inertia | silhouette | 규칙3상태와 ARI | 최대군집 비중 |
|---|---|---|---|---|
| 2 | 8723.8 | 0.520 | 0.181 | 0.669 |
| **3** | 6510.2 | 0.532 | **0.210** | 0.572 |
| **4** | 4557.7 | **0.558 (최적)** | 0.283 | 0.517 |
| 5 | 3602.1 | 0.517 | 0.229 | 0.318 |
| 6 | 3008.4 | 0.524 | 0.213 | 0.314 |

- **[사실]** silhouette 최적은 k=4 이며 k=3 이 데이터에서 선택되지 않는다. inertia 는 단조 감소로 꺾임이 뚜렷하지 않다.
- **[사실]** 규칙 라벨과 KMeans3 의 ARI 0.210 — 두 라벨은 **상당히 다르다**.
- **[해석]** `3` 은 **가설·설계상의 개수**다. 보고서 20의 "4개 정의에서 3구조 재현" 은
  각 정의가 **3개를 전제**했을 때의 일치도이며, 군집 개수 자체의 근거가 아니다. 이 구분을 보고서 20·23에 반영한다.

|---|---|---|---|---|---|
| V2 global+상태특성 | ✗ | ✗ | ✓ | ✗ | **아니오** |

V2(상태를 특성으로)는 h30 단독으로만 유의 개선(−0.116) — 단일 horizon 이득으로 전체 구조를 바꾸지 않는다.

## 3. 오류분석 타당성 재검토 — 원인 설명이 아니라 실패 위치 **[사실]** `30_missed_event_summary.csv`

사전 규칙: ① `forecast_miss` = 예측 여유 < −2×MAE / ② `rule_blocked` = 예측 여유 ≥ −1×MAE 인데 규칙이 막음 /

### 복구 가능성 — ③을 "예측 불가" 로 부를 수 없는 이유 **[사실]**

| 복구 수단 | ① 예측실패 | ② 규칙차단 | ③ 판별불가 |
|---|---|---|---|
| 임계 q0.50 으로 낮추기 | **1.00** | **1.00** | **1.00** |
| 보정확률 ≥ 0.5 | 0.00 | 0.60~1.00 | 0.11~0.60 |
| 다른 확인단계(T−45) | 0.00~0.57 | 0.00~1.00 | 0.00~1.00 |

- **[사실]** 모든 미탐 사건은 조기 임계를 0.50 분위로 낮추면 포착된다(복구율 1.00).
- **[해석]** 따라서 미탐의 1차 원인은 **"예측 불가" 가 아니라 임계 선택(오경보 예산과의 교환)** 이다.
  ③을 센서 부족·본질적 불가로 서술하는 것은 근거가 없다.
- **[사실]** ① 집단은 보정확률도 0.23~0.32 로 낮고 확률 복구 0.00 → 이 집단만이 "현재 입력으로 신호가 약한" 사례다.
  TEST 2건 / LOCK 5건으로 소수다.
- **[해석]** 오류분석의 서술 등급을 **"실패 위치를 보여주는 탐색 결과"** 로 내린다. 보고서 23·28·29 문구를 그에 맞춘다.

## 6. 이후 방향 (4번 현장활용 · 5번 차별성) — **검증 선행 조건부**

현재 경고 성능(포착 0.42~0.53, FN율 0.59)이 검증 기준을 통과하기 전에는 아래를 주장하지 않는다.

- **4번**: 다단계 경고 화면을 늘리지 않는다. **사건당 1회 알림**으로 "평소보다 높은 사용량이 처음 나타날
  예상 시각 + 지금 남은 준비시간(분)" 을 전달하는 설계를 후속으로 검토한다. 이를 **시급함(urgency)** 으로만
  부르고 **위험 심각도·고장 진단으로 부르지 않는다**. 전문가 지식 없는 심각도 순위는 만들지 않는다.
  근거는 UI 가 아니라 제때 포착한 사건 수와 헛경고 부담(스텝/사건/확인분)이다.
- **5번**: '다중 경고' 를 차별점으로 쓰지 않는다. 대신 **수치 예측을 바탕으로 고사용량의 '최초 시작 시각' 을
  예측·검증**하는 방향을 검토한다. 평가 지표는 사건 포착률, **시작 시각 오차(분)**, 확보한 준비시간이며,
  기존 임계 규칙·persistence 기준선보다 셋 다 좋아질 때만 차별점으로 주장한다.
  수치 예측 성능과 이 지표를 **하나의 점수로 섞지 않는다**.

### 이번에 새로 검증한 것
1. 4개 horizon × 4개 변형 × 2개 가정에서 상태별 모델 비교, 일 블록 paired bootstrap → **채택 불가**
2. 군집 개수 자체 점검 → **silhouette 최적 k=4**, 규칙 라벨과 ARI 0.21 → "자연 군집 3개" 주장 철회
3. LOCK 14일·strict_lag 가정에서도 결론 재현
4. 미탐 사건의 ①②③ 분해 + **복구 가능성** → 전부 임계 완화로 포착 가능 → "예측 불가" 서술 금지
5. 상태별 FN/FP 를 **분모와 함께** 산출 → 전환형의 FN율이 오히려 낮음(경고 축)
6. 필수 시각화 4종

### 확인되지 않아 주장할 수 없는 것
- 상태별 모델이 특정 조건(h60 고부하)에서 유리하다는 것 — 부분군 소폭 개선은 전체 악화와 함께 나타나며 사전 조건 미충족
