# A. 조업/비조업 상태 분리가 회귀를 실제로 개선하는가

## A.1 설계
- 상태 정의: `is_operating = (생산량 > 0)`. 생산계획에서 사전 확정되므로 예측 시점에 안다고 간주.
- 기본 특성집합 `FE_BASE` 에서 **생산량·공장인원을 뺐다.** 생산량을 넣으면 상태가 그 함수라 "상태 추가 효과"가 정의상 0 에 수렴한다(공장인원은 생산량과 spearman 0.994).
- 참고선으로 생산량 포함 global 도 함께 보고.
- 세 모델: `global`(상태 없음) / `state_feature`(상태 1개 특성) / `state_specific`(상태별 독립 모델).

## A.4 결론
- **[사실]** 상태 분리는 선형모델(Ridge)에서 MAE를 5.8~10.1% 줄이고 통계적으로 유의하다.
- **[사실]** HGB에서는 `state_feature` 만 유의하며 개선폭은 1.5~2.9%. `state_specific` 은 두 구간 모두 **유의하지 않다**(CI가 0을 포함).
- **[해석]** HGB는 `kw_lag*`·`kw_roll*` 만으로 조업 여부를 이미 암묵적으로 학습한다. 상태를 명시해도 남는 이득이 작다. 상태별 모델 분리는 학습 표본을 쪼개는 손실이 이득을 상쇄한다.
- **[발표용 문장]** "상태 분리는 모델을 바꿀 만큼의 성능 장치가 아니라, **선형·해석형 모델을 쓸 때 반드시 필요한 전제**이며, 비조업 구간 MAE를 3.74 → 2.93 (−22%) 으로 낮추는 **구간별 신뢰도 개선** 수단이다."

# B. 복제(증강) 처리 방식이 실제 성능을 바꾸는가 — Data Reliability Layer 검증

## B.1 설계 (가장 중요)
학습 방식만 4가지로 바꾸고 **평가 집합을 하나로 고정**했다.
- 테스트 = 원본 구간(2021-07-01 이후) 중 마지막 20% = **16일 / 1,536 스텝**. 원본이므로 복제 누출 없음.
- 학습 풀 = 테스트 시작 이전 전체.

| variant | 학습 정의 | 학습 일수 | 학습 행수 |
|---|---|---|---|
| `raw_all` | 복제 포함 전부 | 240 | 23,040 |
| `dedup` | profile_id 당 가장 이른 1일만 | 125 | 12,000 |
| `inv_dup_wgt` | 전부 + sample_weight = 1/profile_n | 240 | 23,040 |
| `clean_only` | 원본 구간(7~9월)만 | 60 | 5,760 |

## B.3 결론 — Data Reliability Layer 는 "학습 기법"으로는 성립하지 않는다
- **[사실]** 중복 제거와 역중복 가중은 raw_all 대비 성능 차이가 **통계적으로 없다**(CI가 0을 가로지름).
- **[사실]** 원본만 쓰는 것은 raw_all보다 **유의하게 나쁘다**(+0.437 MAE). 학습 일수가 240 → 60으로 줄어든 손실이 복제로 인한 오염보다 크다.
- **[해석]** 복제된 날은 "오염 데이터"가 아니라 **정보량이 0에 가까운 중복 표본**이다. 트리모델은 중복 표본에 크게 흔들리지 않는다. 따라서 복제를 제거·가중해도 얻을 게 없고, 데이터를 버리면 손해다.
- **[중요한 구분]** 복제가 해로운 곳은 **학습이 아니라 평가**다. 앞선 분석에서 랜덤 분할 CV가 시간순 분할보다 낙관적이었다(MAE 5.23 vs 5.78, `05_power_forecast_baseline.csv`). 즉 복제의 피해는 **성능 부풀리기**이지 **모델 열화**가 아니다.
- **[발표용 문장]** "증강 복제는 학습을 망치지 않는다. 망치는 것은 평가다. 따라서 대응은 '중복 제거'가 아니라 **'중복 인식 평가 프로토콜(profile-group / 시간순 분할)'** 이어야 한다."
- **[기각]** "중복 제거 / 역중복 가중이 성능을 올린다"는 가설은 데이터가 기각했다.
- **[유지]** "중복이 평가를 부풀린다"는 가설은 유지된다.

# C. Quantile / Conformal 초과수요 점수의 실제 선별력

## C.1 설계
- 타깃 `kw(t+4)` = 1시간 뒤 수요. 시간순 3분할 train 60% / calibration 20% / test 20%.
- `QR` = HistGradientBoostingRegressor(loss="quantile") 분위 예측(보정 없음).
- `CQR` = Conformalized Quantile Regression. calibration 잔차 `E = max(q_lo − y, y − q_hi)` 의 분위로 구간을 보정한다.
- 피크 임계 `thr` = 해당 구간 수요의 p95 (all: 180 kw, clean: 188 kw).
- 경보 규칙: **상한 분위 예측 ≥ thr 이면 경보**.

## C.2 Coverage — 보정은 marginal만 고치고 tail은 못 고친다
`06C_power_conformal_coverage.csv`

| 구간 | 방법 | 목표 | **실제 coverage** | 구간폭 | 조업시 | 비조업시 | **실제 피크일 때** |
|---|---|---|---|---|---|---|---|
| all_2021 | QR(무보정) | 0.90 | 0.818 | 37.2 | 0.789 | 0.858 | **0.188** |
| all_2021 | **CQR** | 0.90 | **0.871** | 40.2 | 0.826 | 0.933 | **0.253** |
| all_2021 | QR(무보정) | 0.80 | 0.670 | 26.5 | 0.671 | 0.670 | 0.084 |
| all_2021 | CQR | 0.80 | 0.793 | 29.3 | 0.719 | 0.896 | 0.114 |
| clean_Jul_Sep | QR(무보정) | 0.90 | 0.766 | 36.6 | 0.805 | 0.667 | **0.368** |
| clean_Jul_Sep | **CQR** | 0.90 | **0.949** | 51.7 | 0.930 | 0.998 | **0.842** |
| clean_Jul_Sep | QR(무보정) | 0.80 | 0.725 | 28.8 | 0.694 | 0.806 | 0.421 |
| clean_Jul_Sep | CQR | 0.80 | 0.827 | 33.3 | 0.776 | 0.958 | 0.579 |

- **[사실]** 무보정 분위 예측은 **모든 경우에 under-cover** 한다(0.670~0.818, 목표 0.80~0.90).
- **[사실]** CQR 보정 후 marginal coverage가 목표에 근접한다(0.871 / 0.949 / 0.793 / 0.827).
- **[사실·핵심]** 그러나 **실제 피크가 난 스텝만 보면 coverage가 0.114~0.842** 로 무너진다. all_2021 90% 구간에서는 **0.253** 에 불과하다.
- **[해석]** conformal 의 marginal coverage 보장은 **"평균적으로 90%"** 일 뿐이며, 우리가 실제로 필요한 **꼬리(극단 수요) 구간에서는 보장이 없다**. 조건부 coverage 붕괴는 conformal 의 알려진 한계이며, 이 데이터에서 정량적으로 재현되었다.
- **[해석]** 비조업 coverage(0.896~0.998)가 조업 coverage(0.719~0.930)보다 훨씬 높다 → 구간이 쉬운 구간에서 과대, 어려운 구간에서 과소다. **Mondrian(조업상태별) conformal** 이 필요하다는 직접적 근거. (A절의 상태 분리가 성능이 아니라 **신뢰구간 품질** 쪽에서 값을 갖는 이유.)

- **[결론]** conformal 의 기여는 **순위(선별력)가 아니라 임계(threshold)의 보정**이다. "conformal 을 쓰면 피크를 더 잘 찾는다"는 주장은 **기각**된다.

| 방법 | 분위 | 경보빈도 | 포착률 | 놓친 피크 | 오경보율 | 정밀도 |
|---|---|---|---|---|---|---|

- **[사실]** 원본 구간에서 피크를 **전부** 잡으려면(포착률 1.000) 하루 28.4회 경보, 정밀도 0.088을 감수해야 한다.
- **[사실]** 하루 10회 경보(분위 0.90) 수준에서는 포착률 0.658, 정밀도 0.170, 피크 13건 누락.
- **[사실]** 전체 구간 수치는 원본보다 훨씬 좋아 보인다(분위 0.95에서 포착률 0.928·정밀도 0.390). 이는 증강 복제 때문이며 **현장 기대치로 인용하면 안 된다**.
- **[해석]** 원본 기준 정밀도 0.09~0.22 는 "경보 5~11회당 1회만 진짜"라는 뜻이다. 15분 수요요금 절감액과 오경보 대응 비용의 비율이 그보다 크지 않으면 이 경보는 **순손실**이다. → **비용 기반 임계 설계가 선택이 아니라 필수**임이 정량적으로 확정되었다.
- **[사실]** CQR 은 낮은 분위에서는 QR 과 거의 같고(0.70~0.85 구간 동일), 높은 분위(0.975, 0.99)에서 포착률을 0.842→0.974, 0.947→1.000 으로 끌어올린다. 대신 경보빈도를 16.5%→21.9%, 23.9%→29.5% 로 올린다.

## C.5 결론
1. **[지지]** conformal 보정은 marginal coverage 를 목표에 맞춘다(0.766 → 0.949).
2. **[기각]** conformal 이 극단수요 **선별력**을 개선한다 — 순위 불변, AUC/AP 동일.
3. **[기각]** 90% 구간이 극단 구간에서도 90%를 보장한다 — 실제 피크 시 coverage 0.253(전체) / 0.842(원본).
4. **[지지]** 조업/비조업 조건부 coverage 격차가 크다(0.719 vs 0.998) → Mondrian conformal 필요.
5. **[지지]** 경보 운용 곡선이 비용 설계의 입력으로 바로 쓸 수 있는 형태로 산출되었다(포착률·누락·오경보·경보빈도·정밀도 동시 제시).
