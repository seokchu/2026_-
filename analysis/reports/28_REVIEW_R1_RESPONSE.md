## 1. P0-1. 동일 목표시각 순차 경보 (`sequential_policy.py`)

### 설계
목표시각 `T` 의 라벨 = `실측수요(T) ≥ thr(T)` (직전 30일 p95, 정의 불변).
- 1단계 조기경보: 결정시점 `T−60`, `pred_h4` (목표 T)
- 2단계 확인 **변형 A**: `T−45`, `pred_h3` → 확인 후 잔여 대응 **45분**
- 2단계 확인 **변형 B**: `T−15`, `pred_h1` → 확인 후 잔여 대응 **15분**
- 상태: `watch → confirmed / rejected`
두 변형은 서로 다른 상품이다(남는 대응시간이 다르다). 하나로 뭉치지 않는다.

시간축 예제 3건: `28_sequential_timeline_examples.csv` **[사실]**
예) `T=2021-08-26 11:00`, 조기 `10:00` 점수 188.48 ≥ 임계 182.89 → watch,
확인 `10:15`(변형 B) 점수 187.06 → confirmed, 실측 193.0 ≥ 임계 190.0 → 포착.
같은 날 `T=09:45` 은 조기 점수 175.05 < 182.89 로 watch 미발생 → 미탐.

## 3. P0-3. 운영상 피크 초과의 보정 확률 (`peak_probability.py`)

정의: `p_h(t) = P( y_{t+h} > thr_t | X_t )`. 폴드별 TRAIN 학습 → **CAL isotonic 보정** → TEST 평가.
운영임계는 CAL F1 최대화로 선택(TEST 미사용).

> **명명 가드**: 이것은 **운영상 피크 초과 확률**이다. 설비 고장 확률·품질 불량 확률·
> KEPCO 계약전력 초과 확률이 **아니다**. 라벨은 전력 수요가 직전 30일 p95 를 넘은 사건뿐이다.

## 7. 남은 작업

1. 평가창이 짧다(15일·17이벤트). 증강구간을 포함한 더 긴 SEL/TEST 로 임계 이전성을 재검증.
